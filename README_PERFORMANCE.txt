[지도] 가장 큰 원인: drawHolos() 안의 ctx.filter = blur(...)
  홀로그램이 흐린 상태(평소 상태)일 때, 구·정육면체·원뿔의 선 약 25개를 그을 때마다 Canvas 블러 필터가 따로 실행됐습니다.
  지도 프레임마다 블러가 약 75번 돌았던 셈입니다.
  같은 조건에서 이 필터만 껐을 때 프레임이 2.2 → 42 fps로 올라 원인이 확정됐습니다.
  (백드롭 블러 제거·CSS 애니메이션 정지는 변화가 없었습니다.)
그 밖의 원인
  - 매 프레임 144개 건물의 꼭짓점(proj)·경로를 새로 계산
  - 건물마다 rgb()/rgba() 문자열과 배열을 새로 생성(가비지 증가)
  - 건물마다 sin + pow(10) + hypot + pow + exp 계산
  - 그라디언트 6~9개를 매 프레임 새로 생성
  - 이동 경로 길이를 매 프레임 다시 계산
  - 핫스팟 transform·클래스와 #exHint 투명도를 매 프레임 DOM에 기록(querySelector 포함)
  - pointermove마다 getBoundingClientRect() 호출
[제품 카드] 포커스가 바뀌는 동안 카드 3장 전체에 blur·brightness·saturate 필터와 큰 box-shadow 문자열을 매 프레임 다시 적용했습니다.

  또 화면 어디에 있든 전역 pointermove에서 getBoundingClientRect()를 매번 호출했습니다.

2. 바꾼 함수와 차이

[지도]
 drawHolos(ctx,time)
  - 이전: 선마다 블러 필터를 적용했습니다.
  - 이후: 선들을 작은 오프스크린 스프라이트에 한 번 그린 뒤 그 스프라이트에만 블러를 1번 적용합니다.
    블러는 선형이고 'lighter' 합성도 선형이라 결과가 같습니다.
  - 흐린 스프라이트는 홀로그램마다 캐시합니다. 다시 만드는 경우는 다음뿐입니다.
    · 회전 때문에 최대 초당 24번
    · 확대 배율이나 밝기가 바뀔 때
    그 사이에는 위치(떠다님·이동·패럴랙스)만 매 프레임 옮깁니다.
  - 구·정육면체·원뿔의 단위 좌표는 처음 한 번만 만듭니다. 매 프레임에는 회전 cos/sin을 홀로그램당 1번만 계산합니다.
  - 빔·글로우·지면 원판의 그라디언트는 밝기 단계별로 캐시해, 단위 공간에서 다시 씁니다.
  - 호버·선택 시 선명해질 때(H≥0.5)는 이전처럼 필터 없이 바로 그립니다.
 drawExplorer(time)
  - buildGeo(): 아래를 지도 크기가 바뀔 때만 만듭니다.
    · 건물마다 왼면·오른면·윗면·테두리·유리창 Path2D, 하이라이트 기준점, 화면 범위
    · 도로·이동 경로 Path2D, 경로 구간 길이와 전체 길이
    · 구역 중심 좌표
  - 색상: 256단계 색상표에서 꺼내 씁니다(문자열·배열 생성 없음, 차이 1/255 이하).
  - 빛의 물결: i+j에만 의존하므로 프레임당 sin 31번만 계산하고, pow(10)은 곱셈으로 바꿨습니다.
  - 마우스 하이라이트: 거리 제곱으로 비교하고, 포인터 근처 건물만 exp를 계산합니다.
  - 확대 시 화면 밖 건물은 그리지 않습니다(빛 상태 값은 계속 갱신).
  - 'lighter' 테두리 글로우는 save/restore 대신 합성 모드만 바꿨다가 되돌립니다.
  - 라임 파티클: 같은 잔상 단계를 하나의 경로로 묶어 fill 40번을 10번으로 줄였습니다.
  - 핫스팟: 캔버스와 같은 변환(패럴랙스 포함)을 쓰도록 맞췄습니다.
    · 위치가 0.05px 이상 바뀔 때만 transform을 기록합니다.
    · hover·act·dim 클래스와 #exHint 투명도는 값이 바뀔 때만 기록합니다.
 initExplorer() 포인터 처리
  - pointermove는 최신 좌표만 저장하고, 처리는 requestAnimationFrame에서 프레임당 1번 합니다.
  - 좌표는 offsetX/Y를 써서 getBoundingClientRect()가 필요 없습니다(클릭도 동일).
 hitZone(): 캐시된 구역 중심을 쓰고 pow를 없앴습니다.
 frame(ts): 바꾸지 않았습니다.
  - 기존 FPS 제한(움직일 때 60 / 정지 시 24)과 near('explore') 가시성 검사를 그대로 둡니다.
  - updateHero·drawMetro·updateIntro·updateMarquee·updateWorld·drawFluid는 이미 각자 near() 검사로 일찍 빠져나가므로, 중복 검사를 추가하지 않았습니다.
  - 탭이 비활성화되면 브라우저가 requestAnimationFrame을 멈추고, 돌아오면 그대로 이어집니다.

[제품 카드] product-carousel-script 다시 작성. 포커스 판정, 순서, 동작, 터치·키보드는 그대로입니다.
  - 카드마다 매 프레임 쓰는 값은 transform과 --f(0→1) 하나뿐이고, 값이 바뀔 때만 씁니다.
  - 흐림: 각 제품 이미지를 처음 한 번 캔버스로 블러(2.2px, 모바일 1.4px)와 채도 0.88을 입힌 사본으로 만들어 두고, 선명한 이미지와 opacity로 교차합니다.
  - 어두워짐: 기존 그늘 레이어 하나로 brightness(.8)와 같은 계산을 합니다(밝기 측정 오차 ±1/255).
  - 글로우·그림자: 퍼플 글로우와 깊은 그림자는 고정 box-shadow 레이어 2장(::before/::after)의 opacity로, 초점 테두리는 1px 링 레이어로 처리합니다.
  - 글자 흐림: text-shadow를 0.25px 단계로만 갱신합니다.
  - 무대 위치(rect)는 캐시해 두고 scroll·resize·레이아웃 변화 때만 다시 읽습니다.
  - 포인터 이벤트는 IntersectionObserver로 섹션이 화면에 있을 때만 받고, 처리는 프레임당 1번입니다.
  - 포커스가 안정되면 requestAnimationFrame을 완전히 멈춥니다(확인).
  - will-change는 섹션이 화면에 있을 때만 켭니다.
  - CSS transition과 JS가 같은 속성을 동시에 건드리지 않도록 border transition을 정리했습니다.
  - 블러 사본이 아직 없으면 이전 방식(CSS 블러)으로 잠깐 대체합니다.
